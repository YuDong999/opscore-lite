# Kibana(ELK/EFK)与 Grafana 前端布局调研报告

> 面向 OpsCore 日志监控平台的补充调研。与本目录下 `loki-research.md`（Grafana Loki/Promtail）、`fluentbit-research.md`（Fluent Bit/Fluentd）配套。
> 本文聚焦：**① Kibana 前端界面布局 ② 索引生命周期管理 ILM 冷热分层 ③ Grafana 面板布局与数据源插件架构**，供 OpsCore 前端模仿与后端建模。

---

## 0. 一句话结论

- **Kibana Discover** 是"**上查询、下结果**"：顶部查询栏(KQL/字段过滤) + 左侧字段面板 + 中下部结果表(柱状时间线 + 文档列表)，点单行在**右侧详情抽屉**看全字段。
- **Kibana Logs/Stream** 是"**实时日志流 + 级别着色 + 上下文查看**"，顶部时间线柱状图 + 下方日志行流，可 live tail。
- **ILM 冷热分层**把索引生命周期拆成 `hot → warm → cold → delete` 顺序阶段，每阶段配 rollover/缩容/冻结/删除策略。**这是 OpsCore"设置冷热归档"的直接范式。**
- **Grafana** 面板是"**数据源无关的盒子**"——用一个 `type` 声明面板类型(logs/time-series/table/gauge)，各数据源插件提供查询与返回格式，面板统一渲染。

## A. Kibana（ELK / EFK 的 K）

### A.1 Discover 页面布局（探索/检索）

Discover 是三块式布局，OpsCore 可直接照抄：

```
┌──────────────────────────────────────────────────────────────────────┐
│ 顶栏: [Discover] 主菜单 | 数据视图(Data view 下拉) | 时间范围 |  ↗跳转  │
└──────────────────────────────────────────────────────────────────────┘
┌─ 工具栏 ────────────────────────────────────────────────────────────┐
│ [KQL查询框: 支持 KQL/Lucene/ES|QL 两种模式] [刷新] [保存] [字段布局] │
│ 过滤器栏: 已应用的筛选(chips, 可移除/编辑)                          │
└─────────────────────────────────────────────────────────────────────┘
┌─ 左侧 ───────────────┬─ 中部结果 ──────────────────────────────────┐
│ 可用字段(可搜索)      │  直方图: 命中文档按时间桶柱状(可框选缩放)    │
│  · 字段名 + 类型      │  文档列表: 展开/折叠, 显示所选字段           │
│  · 点击字段 → 加列/过滤│   · 多行: 时间 + 高亮命中的分析字段 + message│
│  · 字段统计/分布       │   · 点击某行 → 右侧详情抽屉                 │
│ 已选字段(列)          │  分页 / 每页条数 / 采样                     │
└──────────────────────┴──────────────────────────────────────────────┘
┌─ 右侧详情抽屉(点某行浮出) ──────────────────────────────────────────┐
│  文档 JSON / 表格视图: 展示全部字段与值                              │
│  字段值可: 过滤(加/减为条件) / 复制 / 打开字段统计                   │
└──────────────────────────────────────────────────────────────────────┘
```

**关键交互**（供模仿）：
- **KQL（Kibana Query Language）**：`service.name : "order-api" and log.level : "error"`，字段名 + 操作符 + 值。
- **点字段值 = 过滤**：在结果里点任一字段的值，自动加为过滤条件(可为该值 inclusion/exclusion)。
- **高亮命中**：搜索词在结果文档 / message 字段中高亮显示。
- **时间范围**：全局时钟，支持相对(Last 15 min)与绝对区间，绝对/相对直方图联动。

### A.2 Logs / 日志流视图（Stream）

专门给日志的实时视图：

```
┌──────────────────────────────────────────────────────────────────┐
│ 顶栏: 日志数据流选择 | 时间范围 | Live(实时跟随) 开关               │
└──────────────────────────────────────────────────────────────────┘
┌─ 时间线柱状图 ──────────────────────────────────────────────────┐
│  日志条数按时间桶柱状图, 框选缩放                               │
└─────────────────────────────────────────────────────────────────┘
┌─ 日志行列表(实时滚动) ──────────────────────────────────────────┐
│  每行: 时间戳 | log.level(着色) | 服务 | message                 │
│  · ERROR 红 / WARN 橙 / INFO 蓝 / DEBUG 灰                       │

└──────────────────────────────────────────────────────────────────┘
```

### A.3 索引生命周期管理（ILM）→ 冷热归档范式

OpsCore **"设置冷热归档"请求的直接参考**。ELK 把索引生命周期拆为顺序阶段：

| 阶段 | 含义 | 常用策略动作 |
|------|------|-------------|
| **Hot 热** | 频繁写入/查询 | `rollover`(索引达到 max size/docs/age 时滚动到新索引)、`priority=100` |
| **Warm 温** | 少写多读 | 强制只读 `readonly`、`shrink`(缩分片)、`forcemerge`(合并段)、`priority=50` |
| **Cold 冷** | 极少访问但需可查 | `freeze`(冻结/最小化内存) 或迁到慢存储(冷节点)、`priority=0` |
| **Delete 删除** | 数据到期 | 按保留期删除整索引 |

**关键点**：
- 策略按**索引模式/数据流**绑定，每个阶段有一个**触发条件**（多大多老才进入该阶段）。
- 底层是 `hot → warm → cold → frozen → delete` 节点角色分层 + 策略定时巡检。
- **对 OpsCore 的映射**：不需要真的多节点，可"**策略配置 + 数据落盘分区**"模拟——热区 SQLite/ssd 表、冷区压缩归档文件、删除按保留期定时清理。

### A.4 Data View / 索引模式

- **Data View（数据视图，旧称 Index Pattern）**：指一组索引的"入口"，如 `logs-*`，并定义**字段映射**（类型、是否可聚合、是否时间字段）。
- Discover / 可视化 / 告警都基于某个 Data View。
- **对 OpsCore**：就是"**索引(Index)实体**"——对应 Kibana 的 data view + ILM 策略 + 字段映射。

### A.5 可视化与 Dashboard

- 可视化：**柱状图(vertical bar)、线图(line)、直方图(histogram)、饼图、TSVB**——都基于"聚合查询 + 时间桶"。
- Dashboard：一个页面用**网格布局**放多个可视化，可拖拽调整、支持面板间联动(点击一个面板过滤其他面板)。

## B. Grafana

### B.1 面板布局与数据源无关架构

- **Dashboard**：24 列网格系统，面板(panel)占 n 列，可分组(Row 折叠标题)、拖拽、变量(template variable 如 `$service`)。
- **面板类型由 `type` 字段声明**，同一份数据可用不同面板渲染：
  - `timeseries` 时间序列折线/面积
  - `logs` 日志面板：级别着色、live tail、showLabels/showTime/enableLogDetails/dedupStrategy
  - `table` 表格、`gauge` 仪表、`stat` 数值卡、`barchart` 柱状
- **数据源插件**：每个数据源(Loki/Prometheus/ES/MySQL)是插件，实现统一的 `query(datasource, request) → frame` 接口，面板只认返回的数据帧(frame)结构 → **面板与数据源解耦**。

### B.2 Explore 页面

- 顶部查询编辑器 + 时间范围 + Run；下方**时间线柱状图 + 结果**(日志面板).
- Builder/Code 双模式；多个查询并存，结果合并。
- **对 OpsCore**：Explore 布局 = 前面 Loki 报告 6.3 节详述。

### B.3 Alerting（告警）

- 规则(rule)：查询 + 阈值条件 + 周期；评估后进入 pending → firing；通知路由(route) → 联系人(contact point，邮件/Slack/DingTalk/Webhook)。
- 可对日志聚合出的指标设告警(Prometheus-style)。

## C. 整合给 OpsCore 的 UI 布局范式（本平台前端照此实现）

综合 Kibana + Loki + Grafana，一个"Kibana 式日志浏览 + 监控面板"应为：

```
┌─ 顶栏: [登录上下文] [时间范围全局选择] ──────────────────────┐
├─ 侧栏/顶部 tab: 日志检索 | 索引管理 | 匹配规则 | 数据源 | 监控 │
├─ 日志检索页(主界面) ────────────────────────────────────────┤
│   上: 查询构建区                                           │
│      · 数据源/索引选择 · 搜索框(类 KQL) · 标签/字段过滤chips │
│      · level/服务/时间等多条件 · [查询][Live跟随]           │
│   中: 时间线柱状图(可切换 柱状/流线), 框选缩放, 级别着色      │
│   下: 日志行列表(时间戳|级别|标签|message, 级别着色,       │
│        点击展开详情, 字段高亮, 实时滚动)                    │
├─ 索引管理页 ───────────────────────────────────────────────┤
│   索引列表(名称/条数/大小/保留期/存储阶段) · 新建索引        │
│   索引详情: 字段映射 + ILM 冷热归档策略(hot/warm/cold/delete)│
├─ 匹配规则页 ───────────────────────────────────────────────┤
│   规则列表(应用范围/动作/参数) · 可视化规则编辑器            │
│   (参考 fluentbit-research §10 条件规则数据结构)            │
├─ 监控页(替代 Prometheus/Zabbix) ──────────────────────────┤
│   指标面板网格: 折线/柱状/仪表/表格, 变量, 告警             │
└────────────────────────────────────────────────────────────┘
```
