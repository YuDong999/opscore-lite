# 缺口清单与倒模建议 (Project Cartographer Insights)

> 用 project-cartographer 测绘自身模块 + 倒模 Kibana/Grafana/Loki 交互层后得出。
> 按**可借鉴度 × 实现成本**排序。已核对源码，非猜测。

## 高性价比 (后端已备好/前端现成 → 纯前端补, 1~2h)

### G1. 动态字段聚合 → 修复"字段树静态" + 建议下拉真实化 ✅ 首推
- **现状**: `stats/terms` 后端已实现(L43/175:handleTerms)，前端 0 入口 (🕳️)。
  FIELD_TREE 的 source 子项硬编码 `k8s/container/app/file` (L159)，FIELD_HINTS 硬编码 4 条 (L150-155)。
- **倒模**: Kibana 字段分布 (R-04)、Loki Label Browser 动态值 (R-11)。
- **改法**: 前端加一个"字段统计"入口 → `GET /stats/terms?field=source&field=level&field=service` → 用返回值渲染字段树叶子 & 建议下拉。
- **收益**: 消除 3 个 🪝 悬空项; 字段值真实正确; 用户不用猜。
- **成本**: 低。后端不用改，前端 ~40 行。

### G2. 搜索结果高亮命中词 ✅
- **现状**: `kib-hl` CSS 已存在 (kibana.css L303-309)，搜索词 (keyword/level/service) 已进入状态，**但渲染没包 mark**。
- **倒模**: Kibana 高亮 (R-02)。
- **改法**: 结果表 message 列 + 详情抽屉按 keyword 分词正则包 `<mark class="kib-hl">`。
- **成本**: 极低，纯前端 ~15 行。

### G3. 单资源右键导出 (用户上一轮需求) ✅
- **现状**: 映射矩阵确认——delete 端点 🕳️ 未暴露、无任何导出端点。
- **倒模**: Grafana 导出 CSV (R-12) + 用户说的"单流水线导出"。
- **改法**: 最小闭环——在日志源列表/索引列表加"导出此源/此索引的日志"（右键或按钮），后端加一个 `GET /api/logmonitor/export?sources=&indexId=&start&end&format=csv`。
- **成本**: 中（后端 ~40 行 + 前端 ~30 行 + 右键菜单组件通用化）。

## 中性价比 (有意义但需新后端或较大前端)

### G4. 时间直方图框选缩放
- 倒模 R-03。前端直方图已由 `hist+bucketMs` 驱动，加框选改时间窗口。成本中。

### G5. 保存查询 / 查询历史
- 倒模 R-07。KQL+过滤+时间 组合一键存。需要 localStorage 或后端存储。成本中。

### G6. 上下文查看 (Show surrounding)
- 倒模 R-05。详情抽屉加"查看前后 5 条"→ 后端加 `surrounding` 端点。成本中。

### G7. 详情抽屉全字段过滤
- 现状只支持 indexId/service。倒模 R-01：抽屉任意字段值可加过滤(inclusion/exclusion)。成本中。

### G8. Grafana 面板间联动
- 统计页点击级别条→其他图表联动。成本中高。

## 建议的执行顺序

```
本周 (高性价比, 纯前端+小后端):
  ① G1 动态字段聚合 - 一次消灭 3 个🪝, 让字段树/建议"活"起来
  ② G2 命中词高亮 - 排查时一眼定位
  ③ G3 单资源导出 - 你亲口要的需求闭环
下周 (中):
  ④ G4 直方图框选 ⑤ G5 保存查询 ⑥ G6 上下文查看
```

## 直接归因的话

> 你问"还能挖什么功能"，project-cartographer 最值钱的发现是：**后端 `terms` 聚合早就实现了，但前端 68 个交互点里没有一个调用它**。这意味着最高频的"字段值过滤/动态建议"能力其实免费躺在后端，只差一个前端入口。先做 G1，其余缺口会自然露出来。
